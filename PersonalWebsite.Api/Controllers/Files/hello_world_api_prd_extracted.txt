Hello World API Enhancement

1. Product Name

Hello World API

2. Purpose

The purpose of this API is to provide a simple endpoint that confirms the application is running correctly, while also serving
as a training foundation for professional API development patterns.

This API will be used to practice:

3. Current State

The API currently has a basic Hello World endpoint.

Existing Endpoint

GET /api/hello

Existing Response Example

"Hello World"

4. New Feature Request

Add an enhanced Hello World endpoint that accepts a user name and returns a personalized greeting response.

5. Business Requirement

As an API user, I want to send a name to the Hello World API so that I can receive a personalized greeting message.

6. User Story

As an API user,
I want to pass my name into the Hello World API,
so that I can receive a custom greeting message.

GET /api/hello/Franky

11. Service Layer Requirement

Create a service interface and service implementation for the Hello World feature.

Interface Method

Task<ServiceResult<HelloResponseDto>> GetGreetingAsync(string name);

Service Responsibilities

(cid:127) Accept a name value.

(cid:127) Validate the name.

(cid:127) Return validation errors when the name is invalid.

(cid:127) Return a successful HelloResponseDto when the name is valid.

(cid:127) Return ServiceResult<HelloResponseDto> instead of returning raw DTOs directly.

12. Controller Requirement

The controller should stay thin and should not contain business validation logic.

Example Controller Method

[HttpGet("{name}")]
public async Task<IActionResult> GetGreeting(string name)
{
    var result = await _helloService.GetGreetingAsync(name);

    return result.ToActionResult();
}

13. ServiceResult Pattern Requirement

The feature should use the existing ServiceResult pattern.

Expected flow:

Controller calls service
Service returns ServiceResult<T>
Controller calls ToActionResult()
ToActionResult converts the result into the correct HTTP response

Expected HTTP Mapping

Service Error Type

Validation

NotFound

Conflict

Failure

HTTP Response

400 Bad Request

404 Not Found

409 Conflict

500 Internal Server Error

14. Acceptance Criteria

Scenario 1: Valid Name

Given the user passes a valid name
When they call:

GET /api/hello/Franky

Then the API returns:

200 OK

And the response body is:

{
  "message": "Hello, Franky!"
}

Scenario 2: Blank Name

Given the user passes a blank or whitespace name
When the API processes the request
Then the API returns:

400 Bad Request

And the response contains:

Name is required.

Scenario 3: Name Too Long

Given the user passes a name longer than 50 characters
When the API processes the request
Then the API returns:

400 Bad Request

And the response contains:

Name cannot be longer than 50 characters.
